## 논리 데이터 모델링
- 데이터 베이스 개발 과정의 첫 단계
- 업무 분석을 통한 자료의 흐름을 분석하여 현재 사용중인 양식,문서,장표를 중심으로
자료 항목을 추출하여 엔티티와 속성들의 관계를 구조적으로 정의하는 단계

- 특징
    -
    - 비용 절감: 초기 요구사항 수집이 미흡하면 향후 변경 비용이 크게 발생합니다.
    - 의사소통: 이해 당사자 간의 소통 보조 자료로 E-R 모델을 활용합니다.
    - 독립성: 특정 하드웨어(H/W)나 소프트웨어(S/W)에 종속되지 않습니다.

## 함수적 종속성 과 정규화

- 어떤 속성 A의 값이 정해지면 다른 속성 B의 값도 하나로 정해지는 관계
- A->B A가B를 결정한다 / B는A에 의해 함수적으로 종속된다
```
EX) 학번-> 이름 학번을 알면 이름을 알 수 있음
    학번-> 학과 학번을 알면 학과를 알 수 있음
```

- 함수적 종속성 종류 및 정규화 단계
    -
    1. 1단계: 함수적 종속성 찾기 (`제1정규형`: 도메인이 원자값이어야 함)
    2. 2단계: 부분 함수 종속 제거 (`제2정규형`)개념: 기본키의 일부만으로 결정되는 종속성입니다. (주로 복합키일 때 발생)
    3. 3단계: 이행적 함수 종속 제거 (`제3정규형`)개념: 기본키가 아닌 일반 컬럼이 다른 일반 컬럼을 결정하는 경우입니다. 
        - A-> B 이고 B-> C 이면 A-> C 인 관계
    4. 4단계: 다치 종속(MVD) 제거 (제4정규형)개념: 하나의 속성이 여러 개의 값을 가지며, 그 값들이 다른 속성과 서로 독립적인 경우입니다. (표기:A ->> B)
    5.  5단계: 조인 종속(JD) 제거 (제5정규형)

##  논리 데이터 모델 검증하기

- 검증 주체: 업무 분석가, 데이터베이스 엔지니어
- 검증 항목 및 방법:
    - `유형 식별`: 설계 내역서에 정의된 데이터 유형 및 구축 시스템의 업무 관련 데이터 유형을 확인합니다.
    - `입출력 데이터 일치성 확인`: 업무 처리를 위한 입력 데이터와 출력 데이터가 제대로 식별되었는지 확인합니다.
    - `설계서 비교`: 프로세스별 입출력 데이터 목록을 도출하여 기존 설계서의 항목과 일치하는지 비교·검증합니다.
