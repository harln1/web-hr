자료 항목을 추출하여 엔티티와 속성들의 관계를 구조적으로 정의하는 단계

## 함수적 종속성 과 정규화

- 어떤 속성 A의 값이 정해지면 다른 속성 B의 값도 하나로 정해지는 관계
- A->B A가B를 결정한다 / B는A에 의해 함수적으로 종속된다
```
EX) 학번-> 이름 학번을 알면 이름을 알 수 있음
    학번-> 학과 학번을 알면 학과를 알 수 있음
```

- 함수적 종속성 종류 및 정규화 단계
    -
    1. 1단계: 함수적 종속성 찾기 (`제1정규형`: 도메인이 원자값이어야 함)
    2. 2단계: 부분 함수 종속 제거 (`제2정규형`)개념: 기본키의 일부만으로 결정되는 종속성입니다. (주로 복합키일 때 발생)
    3. 3단계: 이행적 함수 종속 제거 (`제3정규형`)개념: 기본키가 아닌 일반 컬럼이 다른 일반 컬럼을 결정하는 경우입니다. 
        - A-> B 이고 B-> C 이면 A-> C 인 관계
    4. 4단계: 다치 종속(MVD) 제거 (제4정규형)개념: 하나의 속성이 여러 개의 값을 가지며, 그 값들이 다른 속성과 서로 독립적인 경우입니다. (표기:A ->> B)
    5.  5단계: 조인 종속(JD) 제거 (제5정규형)

##  논리 데이터 모델 검증하기

- 검증 주체: 업무 분석가, 데이터베이스 엔지니어
- 검증 항목 및 방법:
    - `유형 식별`: 설계 내역서에 정의된 데이터 유형 및 구축 시스템의 업무 관련 데이터 유형을 확인합니다.
    - `입출력 데이터 일치성 확인`: 업무 처리를 위한 입력 데이터와 출력 데이터가 제대로 식별되었는지 확인합니다.
    - `설계서 비교`: 프로세스별 입출력 데이터 목록을 도출하여 기존 설계서의 항목과 일치하는지 비교·검증합니다.

# 2025/5/26(월)       
## 논리 모델링 검증
- 데이터 베이스를 실제로 만들기 전에 분석한 데이터 구조가 업무에 맞게 잘 정리 되었는지 확인하는 과정
    1. 시스템을 만들기 위해 필요한 데이터를 파악 했는지
        -
    - 입력 데이터 , 출력 데이터가 파악 됐는지
    - 데이터가 다른 업무나 시스템 에서도 사용하는지 파악
    - 새롭게 필요한 데이터가 있는지 파악

    2. 현재 운영중인 시스템의 데이터 현황 분석이 이루어졌는지 확인
        -
    - 데이터 베이스 구조 , 분산 백업 현황이 정확히 파악 되었는지
    - 데이터 속성 , 공통코드가 정확히 파악 되었는지
    - 외부 연계 데이터 속성이 정확히 파악 되었는지

    3. 데이터 베이스에 대한 사용자 요구사항이 도출되고 분석 되었는지
        -
    - 볼륨,분산구조 ,제약 조건에 대한 요구사항이 도출 되고 분석되었는지 확인
    - 타 시스템과 연계 데이터에 대한 요구사항이 도출되고 분석 되었는지 확인 
    - 데이터 베이스의 백업 및 복구 정책에 대한 요구사항이 도출되고 분석 되었는지 확인
    - 초기 데이터 구축 방안에 대한 요구사항이 도축되고 분석 되었는지 확인
    - 기존 데이터 의 전환방안에 대한 요구사항이 도출 되고 분석 되었는지 확인 
    - 무결성 , 데이터 보안성 수준에 대한 요구 사항이 도축되고 분석 되었는지 확인

    4. 데이터의 흐름이 명확하게 정의 되었는지 확인
        -
    - 데이터의 흐름 : 데이터가 어디서 생성되고 , 어디로 이동하며, 어디에서 사용되는지 나타내는 것

    - 프로세스별 입출력 데이터가 명확히 정의되었는지 확인
    - 프로세스간 공유 및 연계 데이터가 명확히 정의 되었는지 확인한다
        - 하나의 데이터는 여러 프로세스에서 공유될 수 있다
    
    5. 데이터베이스 설계 기분이 적정히 정의 되었는지 확인한다
        -
    - 데이터베이스의 설계 표준 지점의 작성 여부 및 적절성 확인
        - 데이터 베이스의 설계 표준집점 테이블 컬럼 제약조건을 어떨게 작성할지 정한 문성
    - 데이터 모델 설계 지점의 작성 여부 및 적절성 확인
        - 엔티티,속성, 관계를 어떨게 표현할지 정한 문서
    
    6. 데이터 모델링이 충분하고 적절하게 수행되었는지 확인
        - 
    - 논리 데이터 모델의 개념 완정성 및 정확성 확인
    - 무결정설이 보장이 되었는지 확인
    - 엔티티 간 실제 업무 규칙과 맞는지 확인
    - 모델 관련 산출을 작성의 적합성 및 일관성에 대한 확인

    7. 엔티티 및 프로세스 간의 연관 관계가 명확한지 확인
        -
    - 엔티티 의 프로세스 간 연관관계를 CRUD메트릭스 를 통해 확인
    
    8. 데이터에 대한 접근권한 및 통제가 명확히 분석되었는지 확인
        -
    - 데이터 중요도 및 데이터 암호화 가이드라인 확인하기
    
## 물리 데이터 모델 설계
- 논리 모델을 적용하고자 하는 기술에 맞도록 상세화해가는 과정

### 반정규화
- 정규화를 조금 포기하고, 조화성능을 높이기 위해 데이터를 중복하거나 테이블 구조를 바꾸는 설계 방법

#### 반정규화 하는 이유
- 데이터가 적을때는 괜찮지만 데이터가 많아지면 조회 성능이 느려질수 있다
- 그래서 자주 조회하느 데이터는 일부러 합치거나 중복해서 저장한다

#### 반정규화의 종류
- 중복 테이블 추가하기
- 집계 테이블 추가
- 진행 테이블 추가
- 특정 부분만을 포함하는 테이블 추가

#### 테이블 조합
- 항상 같이 사용되는 두 개 이상의 테이블을 하나로 합치는것

#### 테이블 분할
- 수직 분활
- 수평 분할

#### 테이블 삭제
- 테이블 재정의 나 컬럼의 중복화 로 더이상 사용되지 않는 테이블의 발생 할 경우에 삭제한다

#### 컬럼 중복
- 필요한 해당 테이블의 컬럼을 중복하여 추가한다
