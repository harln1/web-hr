## 프로토콜 (= 규칙/약속)
- 프로토콜은 통신규칙이다
    - 통신규칙: 컴퓨터가 대화할때 지켜야하는 규칙 (사람이 대화시 지키는 규칙과 비슷)

### 프로토콜이 필요한 이유
- 데이터 형식이 제각각
  - 한 컴퓨터는 이름을 먼저보내고 다른 컴퓨턴 나이를 먼저 보내면 해석이 꼬인다.
- 전송중 오류처리 불가
  - 데이터가 중간에 깨지거나 일부만 도착했을 때 다시 보내야 하는지, 버려야 하는지 기준이 필요
- **서로 다른 회사의 장비끼리 통신불가**
    - 서로 통신하려면 공통규칙 필요

## 프로토콜 핵심구성 요소

### 구문(Syntax)
- 데이터의 형식
    - 어떻게 생긴 형태로 보낼건지를 정함
    
- 첫 번째 칸에는 주소
- 두 번째 칸에는 명령어
- 세 번째 칸에는 실제 데이터
```
[첫 번째 칸] [두 번째 칸] [세 번째 칸]
```
#### 첫 번째 칸 = 주소
"이 데이터를 어디로 보낼지"

- 목적지 정보
- 누가 받을지 결정

📌 예시

- IP 주소: 192.168.0.1
- URL: google.com

👉 현실 비유

택배에서 **배송지 주소**라고 보면 된다

#### 두번째 칸 = 명령어
"무슨 작업을 할지"

- 데이터를 조회할지
- 저장할지
- 삭제할지

📌 예시

- GET → 데이터 조회
- POST → 데이터 생성
- DELETE → 삭제

👉 현실 비유

택배에서 **“이 물건 어떻게 처리할지”**

- 전달만 할지
- 반품할지

#### 세번째 칸 = 실제 데이터
"진짜 보내고 싶은 내용"

- 사용자 정보
- 파일 내용
- 메시지

📌 예시

```
{
  "name":"홍길동",
  "age":20
}
```

#### 총

```
[주소]        [명령어]   [데이터]
192.168.0.1   POST       { "name": "홍길동" }
```

👉 해석

- 192.168.0.1로 보내고
- POST 요청을 하고
- 홍길동 데이터를 전달한다

### 의미(Semantics)

- **보내진 데이터가 무엇을 뜻하는지**,그리고 **그 데이터를 받았을 때 어떤 동작을 해야 하는지**를 정하는 규칙
- 데이터의 형식만 정하는 것이 아니라 **그 값이 들어왔을 때 어떻게 해석하고 처리할지** 까지 포함한다
- 의미는 약속이다
- 동작과 연결된다
- 의미는 양쪽이 같아야한다
- 의미는 필드 하나하나에도 적용이 된다

#### 의미가 필요한 이유
- ㅇㅇ 값이 무엇을 의미하고 , 이 값이오면 이렇게 동작한다 다는 규칙이 필요하기 때문

#### 요청메서드

- 클라이언트가 서버에 요청할 때 다음과 같은 메서드를 씁니다.
  - GET
  - POST
  - PUT
  - DELETE
- 이 단어들은 단순한 문자열이 아닌, 각각 의미가 정해져 있습니다.

**GET**

- 데이터를 조회하라는 의미입니다.

**POST**

- 새로운 데이터를 생성하라는 의미입니다.

**PUT**

- 기존 데이터를 수정하라는 의미입니다.

**DELETE**

- 데이터를 삭제하라는 의미입니다.

예를 들어

```
GET /users
```

- 이 요청은 단순히 `GET`이라는 글자를 보낸 것이 아니라, “`/users`에 있는 데이터를 조회하고 싶습니다” 라는 의미를 전달한다.
- 즉, `GET`이라는 데이터의 뜻이 이미 약속되어 있는 것이다.
**HTTP 상태코드**

서버가 응답할 때도 의미가 있는 값을 보낸다.

- 200 → 성공
- 201 → 생성 성공
- 400 → 잘못된 요청
- 401 → 인증 필요
- 403 → 접근 금지
- 404 → 찾을 수 없음
- 500 → 서버 내부 오류
```
예를 들어 `404`는 단순 숫자가 아니다.
- “요청한 자원을 찾을 수 없음” 이라는 의미를 가진다.
- 클라이언트는 이 의미를 해석하고 “페이지를 찾을 수 없습니다” 같은 화면을 보여줄 수 있다.
```

### 타이밍(Timing)

- 데이터를 언제 보내고, 어떤 순서로 보내고, 얼마나 빠르게 보내며, 얼마나 기다릴지 정하는 규칙이다.
#### 타이밍이 필요한 이유

- 한쪽이 계속 데이터를 보냄
- 상대는 아직 준비가 안됨
- 순서가 뒤죽박죽
- 응답이 안 오는데 계속 기다림

- => 통신 오류, 데이터 손실, 프로그램 멈춤 문제가 발생하는걸 방지하기 위해 타이밍 규칙이 필요함

#### 타이밍을 다루는 핵심
**언제 데이터를 보낼 것인가**

- 데이터를 **언제 보내야 하는지**를 정합니다.

</aside>

- 데이터의 **순서가 유지되도록** 합니다.

### TCP(Transmission Control Protocol)

- 송신자와 수신자가 데이터를 주고받을 때, 데이터가 빠지지 않고, 순서대로, 신뢰성 있게 도착하도록 관리하는 프로토콜
- 서버와 안정적으로 연결을 만든다.

### HTTP 또는 HTTPS

- 브라우저가 서버에게 웹페이지를 요청한다.


### 대표적인 프로토콜 종류

- IP는 **데이터를 목적지까지 보내는 역할**을 한다.

**역할**

- 출발지 IP 주소 확인
- 목적지 IP 주소 확인
- 어디로 보내야 하는지 판단

**비유**

IP는 택배 상자의 **주소**와 비슷하다.

**특징**

- 목적지까지 보내는 데 집중한다
- 데이터가 정확히 도착했는지까지는 책임지지 않는다

<aside>

**IPv4**

- 192.168.1.1처럼 우리가 익히 알고 있는 모양새는 IPv4라는 가장 널리 쓰이는 IP 주소체계이다.
- 4마디로 되어있으며 총 32비트로 되어 있어 2의 32제곱, 약 43억개의 고유 주소를 만들어 낼 수 있다.
- 그러나 인터넷이 빠르게 발전하고  PC뿐만 아니라 모바일, 태블릿 등에서도 IP를 사용하게 되자 고유 주소는 빠르게 소진되었고 고갈되기 시작했다.

**IPv6**

- IPv4와 달리 콜론 `:` 을 이용한 구분을 한다.
- 16진수로 표현을 한다.
- 128비트의 공간을 가지고 있기 때문에 생성 가능한 주소가 2의 128제곱으로 무제한에 가까운 숫자만큼 할당이 가능하다.

</aside>

### TCP (Transmission Control Protocol)

- TCP는 **정확하고 안정적으로 데이터를 보내는 프로토콜**이다.

**역할**

- 연결을 먼저 만든다
- 데이터가 빠졌는지 확인한다
- 순서대로 다시 조립한다
- 문제가 생기면 재전송한다

**특징**

- 신뢰성이 높다
- 대신 속도는 약간 느릴 수 있다

**사용하는 예**

- 웹페이지
- 로그인
- 파일 전송
- 이메일

### UDP (User Datagram Protocol)

- **빠르게 보내는 데 집중하는 프로토콜**이다.

**역할**

- 연결 없이 바로 보낸다
- 재전송이나 순서 보장은 거의 하지 않는다

**특징**

- 빠르다
- 대신 일부 데이터가 손실될 수 있다

**사용하는 예**

- 실시간 게임
- 인터넷 방송
- 음성 통화
- 영상 스트리밍

**비유**
- 확성기로 빠르게 여러 사람에게 말하는 느낌이다.

- 조금 놓쳐도 전체 흐름이 중요할 때 사용한다.

### HTTP (HyperText Transfer Protocol)

- **웹 브라우저와 웹 서버가 대화하는 규칙**이다.

**역할**

- 브라우저가 서버에 요청한다
- 서버가 응답을 준다

**예시**

브라우저:

`GET /index.html`

서버:

`200 OK`

**특징**

- 웹에서 가장 많이 쓰인다
- 텍스트 기반으로 이해하기 쉽다

### HTTPS

- **HTTP에 보안 기능을 추가한 것**이다.

**역할**

- SSL 인증서를 사용하여 사이트에 제공하는 데이터를 암호화해서 전송한다
- 중간에서 훔쳐낸다고 하더라도 데이터가 암호화되어있기 대문에 해독할 수 없다.

<aside>

SSL(Secure Sockets Layer)

- 보안 연결을 만들어주는 기술이다.
- 데이터를 암호화 해준다.
- 이 서버가 진짜가 맞는지 인증을 해준다.
- 데이터를 변조할 수 없어 무결성을 증명한다.

</aside>

#### 사용하는 예

- 로그인
- 결제
- 회원가입
- 거의 모든 현대 웹사이트

 

#### FTP

- FTP는 **파일 전송용 프로토콜**이다.

**역할**

- 서버에 파일 업로드
- 서버에서 파일 다운로드

**예시**

- 웹서버에 이미지 올리기
- 자료실 파일 내려받기

## OSI 7 계층 (중요 무조건 시험에 나옴)
- 컴퓨터끼리 통신할때 어떤 일을 단계별로 나눠서 처리하는 구조

- 데이터를 한번에 막 보내는게 아니라 역할을 7단계로 나눳거 보내고 받도록 정리한 개념

### OSI 7계층이 필요한이유 
- 예전에는 컴퓨터 제조사나 시스템마다 통신 방식이 제각각이라 사용이 어려웠음

- 국제표준화기구 (ISO) 가 통신 과정을 단계별로 나눠서 표준처럼 이해하자

1. 통신과정을 쉽게 이해할수 있다
- 복잡한 통신을 한번에 보면 어렵기 때문에 기능을 층별로 나눠서 본다

2. 문제가 생겼을때 어디서 고장났는지 찾기 위해서

- 예를들어 인터넷이 안될때

- 케이블 문제인지 IP문제인지 프로그램 문제인지 구별해서 볼수있게된다

3. 장비와 기술의 역할을 정리하기 위해

- 허브 , 스위치 , 라우더 , IP , TCP ,브라우저 ,웹서버 와 같은 것들이 어느 계층에서 동작하는지 구분할 수 있다

### 각 계층
1. `1계층` : 물리계층(Physical Layer)
    - 
    - 데이터를 실제로 보내는 계층이다
    - 전기신호 , 빛 , 무선 신호 처럼 눈에 보이지 않는 실제 신호로 데이터를 전달한다
    - 랜선 ,광케이블,허브,리피터,무선전파,커넥터
      - 허브(=공유기) (여러 컴퓨터를 연결하는 장치)
      - 리피터 : 약해진 네트워크 신호를 다시 강하게 만들어주는 장치

    - 이계층의 특징
      -
     - 데이터의 이미는 모른다
      - 그냥 신호를 보냄
      - 문자인지 이미지인지는 식별가능
      - 오직 비트(0,1) 수준으로 처리한다

2. `2계층` : 데이터 링크 계층 (Data Link Layer)
    -
    - 같은 네트워크(LAN) 내에서 장치 간에 데이터가 정확히 전달되도록 돕습니다.

    - 핵심 요소: 물리 계층에서 온 신호의 오류를 검출하고, MAC 주소를 통해 물리적인 목적지를 찾아갑니다.

      - 이계층의 주요 역할
        -
        - 프레임 단우로 데이터 구성
        - 같은 LAN 안에서 목적지 찾기
        - 오류 확인
        - MAC 주소 기반 전달

      - 대표장비
        -
        - 스위치 : 여러 장치를 연결하면서 필요한 장치에게만 데이터를 전달하 는 네트워크장비
          - 목적지 장치에만 전송
          - 충돌거의 없음
          - 속도가 빠르다

          - <-> 허브는 모든 장치에게 데이터를 전송(비효율)
          - 충돌 발생이 많다
          - 보안취약

3. `3계층` : 네트워크 계층 (Network Layer)

    -
    -서로 다른 네트워크를 넘어 목적지 까지 길을 찾는계층 *IP주소가 가장중요*
    - 데이터 상태 : Packet
    
      -**IP주소**
      - 인터넷이나 네트워크에서 장치를 식별하기 위한 논리적 주소

      
    - 이 계층의 핵심역할
      -
      - 목적지 IP 주소확인
      - 어느경로로 갈지 결정
      - 여러 네트워크를 거쳐 전달

    - 대표장비
      -
      -라우터(Router)
      - 서로 다른 네트워크를 연결하고 데이터를 목적지까지 가장 적절한 경로로 보내는 장치

4. `4계층` : 전송 계층 (Transport Layer)
    -

    - 역할: 양 끝단(End-to-End)의 사용자 간에 신뢰성 있는 데이터 전송을 보장합니다.
    - 핵심 요소: 포트(Port) 번호 (어떤 프로그램으로 보낼지 결정)
    - 주요 프로토콜:
      - 
      - **TCP**(안정적): 꼼꼼하게 확인하며 보냅니다. (데이터 유실 없음, 신뢰성 높음)
      - **UDP**: 확인 없이 빠르게 보냅니다. (실시간 스트리밍, 영상 통화 등에 사용)
      - 단위: 세그먼트(Segment)

5. `5계층` : **세션**계층( Session Layer )
    -
    - 통신 연결을 시작하고, 유지하고 , 끝내는 역할을 한다

    - **세션(=전화통화)** *세션매우중요*
      -
      - 전화를 건다 - 연결의 시작
      - 대화를 한다 - 세션의 유지
      - 전화를 끊는다 - 세션을 끊는다
      - 통신 흐름의 연결상태(세션이 살아있다=통신 흐름 연결)
      

    - 역할
        -
        - 연결시작
        - 연결유지
        - 연결종료
        - 대화 동기화

    - 필요한 이유
      -
      - 두 프로그램이 데이터를 주고받을 때 아예 연결상태를 관리하지 않으면 중간에 끊켰는지, 계속 대화 중인지 파악하기 어렵다
6. `6계층` : 표현계층(Presentation Layer)
    -
    - 데이터를 서로 이해할 수 있는 형태로 바꾸는 계층

    - 보내는 쪽과 받는 쪽의 데이터 표현 방식이 다를 수 있기 떄문에 그 차이를 맞춰 주는 역할을 한다

    - 주요역할
      -
      - 데이터 형식 변화
      - 문자 인코딩 처리
      - 암호화 / 복호화
      - 압축 / 해제
7. `7계층` : 응용계층( Application Layer)
    - 
    - 사용자가 실제로 접하는 네트워크 서비스 계층이다

    - 우리가 프로그램을 통해 사용하는 웹, 이메일,파일전송 과 같은 서비스가 이 계층과 가깝다


    - 보낼때 
      -
      -  ex) 사용자가 웹 브라우저에서 사이트 접속을 요청한다
      1. 응용계층
      - 브라우저가 HTTP 요청을 만든다
      2. 표현계층
      - 필요한 형식변환 , 암호화 등을 처리한다
      3. 세션계층
      - 통신 연결 흐름을 관리한다
      4. 전송계층
      - TCP 를 사용해 데이터를 잘게 나누고 포트 번호를 붙인다
      5. 네트워크 계층
      - IP주소를 붙여 목적지를 정한다
      6. 데이터 링크 계층
      - MAC 주소를 붙여 같은 구간에 전달 할 수 있게한다
      7. 물리계층
      - 전기 신호나 무선 신호로 실제 전송한다

## 1. 미들웨어

- `클라이언트와 서버 사이에서 중간 역할을 수행`하는 소프트웨어(또는 코드)**를 의미한다.
- **요청(Request)과 응답(Response)이 오고 가는 과정에서 “중간에 끼어들어 처리해주는 역할”**이라고 이해하면 된다.
- 운영체제 위에서 응용프로그램이 더 편하게 실행될 수 있도록 도와준다. 
- 쉽게 말하면 개발자가 만든 프로그램이 혼자서 바로 하드웨어와 직접 대화하는 것이 아니라, 중간에서 **실행 환경, 연결, 처리, 보안, 트랜잭션 같은 기능을 제공해 주는 소프트웨어**가 미들웨어이다.

            - 회복관리
              - 시스템 오류 및 장애로 인한 데이터 손실 및 결함의 대응
            - 성능
              - 데이터 처리 속도 확보를 위한 실행 계획의 최적화
            - 보안관리
                - 비인가 사용의 접근 제어 및 중요한 정보의 암호화

        - 데이터 베이스 관리 시스템의 유형
          - 
          - 계층형 
            - 트리구조로 데이터 저장(부모 - 자식 관계형성)
            - 자식은 하나의 부모만 가진다
            - 데이터 접근속도 빠름 , 구조는 단순하다
            - 구조 변경이 어려움 , 유연성 부족, 관계가 복잡해지면 관리 어려움
          - 네트워크 형
            - 그래프 구조 , 데이터간 다대다 관계가능
            - 데이터 노드와 관계를 링크로 연결
            - 복잡한 관계표현 가능, 데이터 무결성 높음
            - 구조가 복잡함, 설계, 유지보수가어려움
          - 관계형 ( 주로 사용 )
            - 테이블 형태로 데이터를 저장
            - 행과 열로 구성이 되어있다
            - SQL 사용 , 스키마 기반 , 정규화 지원
                - 스 키 마 : 데이터를 어떻게 저장할지 미리 정의해둔 구조
            - 직관적 , 표준 SQL 지원 , 데이터 무결성 보안 우수
            - 대규모 데이터 처리시 성능저하 가능

            - 종류:
              - Oracle, MySQL , postgreSQL , MSSQL
                    
            - 객체 지향형
              - 객체 단위로 데이터 저장 , 속성과 메서드 포함
              - 객체지향 언어와 연동 용이 , 상속 다형성 지원
              - 복잡한 데이터 구조를 직접 표현가능 , 재사용성이 높다
              - 표준화 부족 , 학습 곡선이 높다(=> 어렵다 ㅠ.ㅠ)
 
            - 객체 관계형
                - 관계형 데이터 베이스에 객체 지향 개념을 추가
                - 대용량 멀티미디어 처리 가능
                - 기존 RDMS 장점을 유지, 복잡한 데이터 처리 가능
                - 구현이 복잡 , 성능 최적화 어려움

            - DBMS 별 특징
              - 
              - 관계형 
              -
              - MYSQL : 오픈소스 , 널리 사용됨 , 안정성 높음
              - Oracle : 기업용 시장 점유율 1위, 대용량 데이터 처리에 강력함, 비용 높음
              - PostgreSQL : 오픈소스, 표준 SQL 준수율 높음, 복잡한 쿼리 처리에 유리
              - MariaDB : MySQL과 호환됨, 오픈소스, MySQL보다 성능 및 기능 개선 지향

              - 비관계형
              -
              - MongoDB : 문서  지향 ,스키마 없음 , 수평적 확장유리
              - Redis : 키-값 구조 ,인메모리방식  ,매우 빠른속도
              - Cassandra : 대용량 데이터 분산 처리 ,고가용성 , 페이스북에서 개발
              - DynamoDB : AWS 관리형 서비스  , 서버리스 , 확장성 및 성능 우수

              - [요약]
            - 관계형 (RDBMS): 데이터를 표(Table) 형태로 관리하며, 데이터 간의 관계를 중요시함 (MySQL, Oracle 등).
            - 비관계형 (NoSQL): 정해진 규격 없이 자유로운 형태로 데이터를 저장하며, 대용량 처리에 유리함 (MongoDB, Redis 등)


                        
                        

              





           




**실시간 데이터 처리 CEP(Complex Event Processing, 복합 이벤트 처리)**

- **다수의 소스에서 발생하는 방대한 이벤트 스트림을 실시간으로 분석하여, 의미 있는 패턴이나 복잡한 상황을 탐지하고 즉각적으로 대응하는 기술**
- 실시간 발생하는 다양한 데이터를 조합하여 복잡한 상황에 대한 이벤트 또는 유형을 추론하는 방식
